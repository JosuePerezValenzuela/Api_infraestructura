# Design: Redis Cache — Tipo-Ambiente

## Technical Approach

Exact same pattern as `redis-cache-catalog` (tipo-bloque). Layer `CacheService.getOrSet` on the list use case and `CacheService.invalidateNamespace` on write use cases.

## Architecture

```
┌─────────────────────────────────────────────────┐
│              TipoAmbienteModule                  │
│  ┌──────────────────────────────────────────┐   │
│  │              Use Cases                    │   │
│  │  ListTipoAmbientes ───getOrSet──┐        │   │
│  │  CreateTipoAmbiente ─invalidate─┤        │   │
│  │  UpdateTipoAmbiente ─invalidate─┤ Cache  │   │
│  │  DeleteTipoAmbiente ─invalidate─┤Service │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

## Data Flow

### Read (list)

```
execute(params) → build options → build key via CacheKeyBuilder
  → service.getOrSet(key, ttl, () => repo.list(options))
```

### Write (create/update/delete)

```
execute(payload) → validate → repo.create(payload) → invalidateNamespace('tipo_ambiente:*') → return
```

## Key Format

Generated by `CacheKeyBuilder.list('tipo_ambiente', params)`:
- `tipo_ambiente:list:limit=8&page=1` (sorted query-string params)

Full list: includes `limit`, `page`, `search`, `orderBy`, `orderDir`, `activo`.

## Cache Keys for Invalidation

`invalidateNamespace('tipo_ambiente:*')` — single wildcard covers all list variations.
